## 避けたい既定パターン

次の型は、題材と無関係に出やすいものです。意図して使うときだけ、理由を残して許可します。

- 青から紫へのグラデーションは使いません。
- 見出しやボタンに絵文字は置きません。
- `LIVE` のような飾りバッジは置きません。
- 根拠のない `10,000+ users` や `Trusted by` は書きません。
- `delve` のような定型的な英語は書きません。
- 不要な補足ラベルや説明文は足しません。レイアウトで伝えます。

このサイトで加えて避ける型は、次に書きます。

- 未記入

Frontend design が繰り返しやすい見た目として挙げるものは、避ける場合だけここに足します。

## 検査の例外

`bun run lint:design` は `site/` の HTML と CSS を検査します。サイトの HTML に書いた日本語は、`bun run lint:docs` が文書と同じ textlint 設定で検査します。

許可の指定は `design-lint.config.json` へ書きます。近い箇所はソースのコメントでも許可できます。

ファイル単位の例です。

```json
{
  "allow": [
    {
      "rule": "vocabulary",
      "path": "site/about.html",
      "text": "delve"
    }
  ]
}
```

`path` を省くと、その規則は全ファイルが対象です。一致した文言だけを許可したいときは `text` を書きます。省いたときは、その規則をまとめて許可します。

`path` はリポジトリからの相対パスです。`*` と `**` を使えます。

コメントは HTML では `<!-- -->` です。CSS では `/* */` です。コメントの中身は、その指示だけにします。

- 同じ行では `design-lint-allow: gradient` と書きます。
- 次の行では `design-lint-allow-next: vocabulary` と書きます。
- 範囲は `design-lint-allow-start: badge` から始め、`design-lint-allow-end: badge` で閉じます。
- ファイル全体では `design-lint-allow-file: emoji` と書きます。

規則名は `gradient`、`emoji`、`badge` です。加えて `social-proof`、`vocabulary`、`*` も使えます。検出する語の一覧は `scripts/check-design.mjs` にあります。
